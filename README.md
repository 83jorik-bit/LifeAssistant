# Жизненный навигатор — Android MVP

Прототип приложения из концепции «Жизненный навигатор»: карта потребностей, бюджет по категориям,
контроль подписок и личный ИИ-помощник. Все данные в этой версии — **моковые** (см.
`data/repository/MockRepository.kt`), реальных интеграций с Яндекс Картами, банками и
маркетплейсами нет — это отдельный этап (см. «Что дальше» ниже).

## Стек

- Kotlin + Jetpack Compose (Material 3)
- Архитектура: MVVM (ViewModel + StateFlow), один экран = один ViewModel
- Навигация: Navigation-Compose, нижнее меню с 4 разделами
- Данные: `MockRepository` — синглтон с тестовыми данными, имитирует сетевую задержку

## Структура проекта

```
app/src/main/java/com/lifenavigator/app/
├── MainActivity.kt                  — точка входа, Scaffold + нижняя навигация
├── data/
│   ├── model/Models.kt              — модели: PlacePoint, BudgetCategory, Subscription…
│   └── repository/MockRepository.kt — источник тестовых данных (замена на реальный API)
└── ui/
    ├── navigation/NavGraph.kt       — маршруты и пункты меню
    ├── theme/Theme.kt               — цвета/тема Material 3
    └── screens/
        ├── map/            — Карта потребностей (список точек + фильтры)
        ├── budget/          — Бюджет по категориям с прогресс-барами
        ├── subscriptions/   — Подписки: список, переключатель вкл/выкл
        └── assistant/       — Чат с ИИ-помощником (ответы по ключевым словам)
```

## Как собрать и запустить

1. Установите **Android Studio** (Koala или новее).
2. Откройте папку `LifeNavigator` как проект (File → Open).
3. Дождитесь синхронизации Gradle (подтянет зависимости автоматически — нужен интернет).
4. Запустите на эмуляторе или устройстве (Shift+F10 / кнопка Run), минимальная версия Android — 8.0 (API 26).

Если у вас нет Android Studio, можно собрать через терминал (нужен установленный Android SDK):

```bash
./gradlew assembleDebug
# APK появится в app/build/outputs/apk/debug/app-debug.apk
```
Готового `gradlew` (Gradle Wrapper) в архиве нет — при первом открытии в Android Studio она
сама предложит его сгенерировать. Либо соберите через локально установленный Gradle:
`gradle assembleDebug` (см. также автосборку через GitHub Actions ниже).

## ⚠️ Full-версия MapKit SDK нужна для реального поиска

Поиск организаций в MapKit доступен только в **full**-версии библиотеки (в `app/build.gradle.kts`
используется `com.yandex.android:maps.mobile:...-full`, а не `-lite`, как в первых версиях этого
проекта). Ключ при этом остаётся тем же самым — просто у full-версии больше возможностей
(поиск, геокодирование, маршрутизация, панорамы) и она немного тяжелее по размеру APK.

Бесплатное использование MapKit (включая full-версию) возможно при соблюдении условий Яндекса:
https://yandex.ru/dev/commercial/doc/ru/concepts/mapkit — там же уточняйте актуальные лимиты,
если планируете реальную нагрузку, а не тестирование.

## Обновление без удаления приложения

Раньше новую сборку приходилось ставить только после удаления старой — Android ругался на
несовпадение подписи. Причина: Gradle подписывал debug-сборки локальным ключом
`~/.android/debug.keystore`, а он на вашем компьютере и на раннере GitHub Actions разный.

Теперь в репозитории лежит общий ключ `keystore/lifenavigator-debug.keystore`, и он прописан
в `app/build.gradle.kts`. Все сборки — и локальные, и из Actions — подписываются одинаково,
поэтому APK просто накатывается поверх установленного, данные и иконка сохраняются.

Поставить обновление можно как обычно (открыть APK на телефоне) или командой:

```bash
adb install -r app-debug.apk
```

**Про безопасность:** это ключ только для debug-сборок, и он намеренно лежит в репозитории
в открытом виде — иначе его не получилось бы использовать и локально, и в CI. Для публикации
в Google Play нужен отдельный release-ключ, который в репозиторий класть нельзя: его хранят
в секретах и никому не показывают.

## Маршруты из карточки места

- **Машина / Транспорт / Пешком** — открывают Яндекс Карты (параметр `rtt=auto|mt|pd`
  из официальной документации URL-схемы).
- **Самокат** — передаётся `rtt=sc`. ⚠️ Это значение в документации Яндекса **не описано**,
  оно подобрано по аналогии и не проверено. Если приложение откроет маршрут не в режиме
  самоката — код другой (при нераспознанном `rtt` Яндекс берёт режим из прошлой сессии).
- **Такси** — отдельная официальная ссылка Яндекс Go
  (`https://3.redirect.appmetrica.yandex.com/route?...`). Если Go не установлен, ссылка ведёт
  на его страницу в магазине приложений.

## Категории, фильтры и сортировка

- Категории: аптеки, продукты, клиники, красота, пункты выдачи, кафе и рестораны,
  одежда и обувь, образование, транспорт. Их можно **комбинировать** — чипы работают
  независимо, «Все» сбрасывает фильтр.
- Сортировка: сначала по удалённости с шагом 0,1 км, внутри одного шага — по оценке
  от высокой к низкой.
- Подписи меток на карте тёмно-оранжевые и пропадают при отдалении (порог
  `LABELS_MIN_ZOOM` в `MapScreen.kt`). Настоящей жирности у подписей в MapKit нет —
  плотность достигается размером и широкой белой обводкой.

**Транспорт:** категория ищет наземные остановки, трамвайные, метро, железнодорожные
станции и платформы электричек, автовокзалы, речные вокзалы и причалы (по ним запрашиваются
не только организации, но и топонимы). Для остановок в карточке остаются только маршруты
пешком и на самокате, а кнопка внизу называется «Маршруты».

Чтобы открывалась именно карточка остановки с проходящими маршрутами, а не организация с
отзывами, используется **собственный URI объекта** из `UriObjectMetadata` (вида `ymapsbm1://…`).
Обрабатывает ли приложение Яндекс Карт эту схему, в документации не описано, поэтому в
`YandexMapsLauncher.openPlaceCard` выстроена цепочка запасных вариантов: URI объекта → карточка
организации по `oid` → поиск по названию → веб-версия. Сами линии транспорта внутри приложения
**не рисуются** — это отдельная задача.

## Карта, метки и подписи

- Метки — значки категорий: белый кружок с эмодзи категории внутри (рисуется в
  `categoryMarkerBitmap`, отдельных векторных иконок под каждую категорию нет).
- По метке можно тапнуть — откроется та же карточка места, что и из списка
  (идентификатор места лежит в `userData` метки).
- Подписи появляются только начиная с 18-го зума (`LABELS_MIN_ZOOM`), до этого
  на карте только значки.
- У каждой категории свой цвет (`NeedCategory.colorArgb`), и он применяется
  единообразно: кайма значка на карте, подпись метки и надпись категории в фильтре.
- Чужой слой точек интереса скрыт (`HIDE_POI_STYLE`), подложка не тронута.

## Меню, вход и настройки

Компактная шапка вместо полноразмерного `TopAppBar` — он занимал заметную часть
экрана впустую. В шапке кнопка меню с двумя пунктами:

- **Войти** — честная заглушка. Настоящая аутентификация требует сервера (хранение
  учётных записей, выдача токенов) либо входа через готового провайдера вроде Яндекс ID.
  Нерабочей формы логина здесь нет намеренно.
- **Настройки** — радиус поиска (1/3/5 км). Настройка настоящая: сохраняется между
  запусками и сразу применяется к поиску.

## Данные между запусками

Моковых мест в списке больше нет. Последний результат поиска сохраняется
(`PlacesCache`, SharedPreferences + JSON) и показывается при следующем запуске,
пока не обновится геолокация. При самом первом запуске список пуст — до первого поиска.

## Транспорт: расписание и билеты — что реально возможно

Кнопка в карточке остановки называется «Расписание и маршруты». Для остановок она НЕ
использует `oid` организации: часть станций заведена в Яндексе ещё и как организация, и
открытие по `oid` приводило на обзор с отзывами вместо расписания. Используется собственный
URI объекта из `UriObjectMetadata`, затем поиск по названию.

**Прямой ссылки «открыть расписание конкретной остановки» у Яндекса в открытом виде нет.**
Официальная URL-схема `yandexmaps://` поддерживает только карту, метку, поиск и маршрут —
параметров для расписания или карточки остановки в ней не описано. Что есть на самом деле:

- **API Яндекс Расписаний** (`yandex.ru/dev/rasp`) — бесплатный, но по отдельному ключу,
  который выдают по заявке. Даёт расписание по коду станции, список ближайших станций к точке
  и коды станций. Важное ограничение из их же документации: он про **междугородний** транспорт
  (электрички, поезда, автобусы, паромы, самолёты), а для городских остановок и маршрутов
  Яндекс прямо отсылает обратно к API Карт.
- **API Яндекс Билетов** — существует, но это партнёрский API: нужен договор, просто так
  подключиться нельзя.

Поэтому кнопка «Расписание и билеты» (показывается для вокзалов, аэропортов, портов и касс)
ведёт на поиск по названию станции в Яндекс Расписаниях — оттуда доступны и рейсы, и покупка
билета. Чтобы открывать страницу станции напрямую (`rasp.yandex.ru/station/<код>`), нужен код
станции, а он выдаётся только через API Расписаний — то есть требуется отдельный ключ.

**Ограничения текущей реализации поиска** (`YandexSearchRepository.kt`):
- На карте скрыт чужой слой точек интереса (`HIDE_POI_STYLE` в `MapScreen.kt`) — подписаны
  только наши места из списка. Подложка (дороги, дома, улицы) не тронута. Чтобы убрать
  что-то ещё, в стиль добавляется нужный тег из документации MapKit «Стили карты».
- На каждую категорию идёт **несколько** поисковых запросов («продукты», «супермаркет»,
  «магазин у дома» и т. д.), результаты объединяются и чистятся от дублей по идентификатору
  организации. Одна формулировка выдавала далеко не всё: сети вроде «Магнита» и маленькие
  кофейни просто не попадали в первую страницу. Размер страницы увеличен с 10 до 30.
  Побочный эффект: с ростом числа категорий и формулировок одно обновление списка — это
  уже **около 31 запроса** к поиску. На бесплатном лимите MapKit (25 000 запросов в сутки)
  это примерно 800 обновлений в день на весь проект — для личного использования запас
  большой, но при росте аудитории это первое, что упрётся в потолок.
- Область поиска передаётся как `BoundingBox`, а не `Circle`: поиск MapKit поддерживает только
  point, boundingBox, polyline и polygon, а на круг нативная библиотека падает без внятной ошибки.
- Используется `SearchManagerType.ONLINE`, потому что офлайн-карты мы нигде не скачиваем и искать
  в офлайн-кэше не в чем. В примерах документации используется `COMBINED` — если понадобится
  офлайн-режим, менять нужно в `YandexSearchRepository`.
- **Тексты отзывов и фотографии MapKit SDK не отдаёт.** В SDK есть только счётчики
  (сколько оценок и сколько отзывов) — сами тексты в составе метаданных отсутствуют.
  Поэтому за отзывами приложение отправляет пользователя в Яндекс Карты по кнопке
  (`YandexMapsLauncher.kt`), а не показывает их у себя.
- Маршрут строится не внутри приложения, а передаётся в Яндекс Карты по URL-схеме
  `yandexmaps://...&rtext=...&rtt=...`. Если приложения нет — открывается веб-версия.
  Рисовать маршрут прямо на нашей карте тоже возможно (в full-версии есть маршрутизация) —
  это отдельная задача, пока не сделана.
- «Онлайн-оплата» и «есть подписка» для реальных точек всегда `false` — это специфичные для
  концепции приложения признаки, которых нет в данных Yandex Business напрямую.
- Категории «Транспорт» и «Саморазвитие» не участвуют в реальном поиске (они больше про бюджет/
  подписки, чем про точки на карте) — как и в тестовых данных, там будет пусто.
- Поиск идёт в радиусе 3 км от пользователя, до 10 результатов на категорию.

## Настройка API-ключа Yandex MapKit (обязательно перед сборкой)

Ключ **не хранится в коде и не коммитится в git** — он читается из файла `local.properties`
в корне проекта (этот файл уже в `.gitignore`).

1. В корне проекта скопируйте `local.properties.example` в `local.properties`
2. Впишите туда свой ключ:
   ```
   MAPKIT_API_KEY=ваш-ключ-здесь
   ```
3. Пересоберите проект (Build → Rebuild Project в Android Studio)

**Важно:** если этот ключ раньше был выложен в открытом GitHub-репозитории — его стоит
**перевыпустить** в кабинете разработчика Яндекса (https://developer.tech.yandex.ru/),
старый лучше отозвать: публично засвеченный ключ может использовать кто угодно, и лимиты
запросов будут расходоваться не вами.

Как получить/перевыпустить ключ:
1. Зайдите на https://developer.tech.yandex.ru/
2. Раздел «MapKit Mobile SDK» → создать новый ключ (или отозвать старый и выпустить новый)
3. Убедитесь, что в настройках ключа разрешён `applicationId` вашего приложения:
   `com.lifenavigator.app`

## Что дальше (не реализовано в этой версии)

Каждый пункт — отдельная задача, требующая внешних ключей/договоров:

1. **Банковские API** — синхронизация транзакций (обычно через агрегаторов вроде Точка API,
   Тинькофф API или Open Banking). Требует согласия пользователя, шифрования, возможно PCI DSS.
2. **Реальный ИИ-помощник** — заменить `MockRepository.getAssistantReply()` на вызов LLM (например,
   Anthropic API) с контекстом бюджета и подписок пользователя.
3. **Бэкенд** — сейчас всё в памяти приложения. Нужен сервер (REST/GraphQL) + база данных для
   хранения профиля, истории трат, поставщиков.
4. **Оплата и маркетплейс** — интеграция с платёжным провайдером (ЮKassa, CloudPayments) и
   каталогами поставщиков.
5. **Публикация** — аккаунт разработчика Google Play, прохождение модерации, политика
   конфиденциальности (обязательна из-за работы с финансовыми данными).
6. **Реальный рейтинг мест** — возможно, доступен через отдельные поля MapKit
   (`BusinessRating1xObjectMetadata`/`BusinessRating2xObjectMetadata` встречаются в SDK), но я не стал
   их подключать без проверки на реальной сборке — стоит изучить отдельно.

## Известные ограничения прототипа

- Данные не сохраняются между запусками (нет базы данных/Room).
- Ассистент не «умный» — просто подбирает готовый ответ по ключевым словам.
- Маршрут «за один выезд» из концепции ещё не реализован (нужен Yandex Routing API).
