# LifeNavigator — сервер хранения пользовательских данных

Минимальный, но настоящий рабочий сервис: Node.js (Express) + SQLite. Хранит ровно
то, что раньше жило только на устройстве, — профиль, согласие на обработку
персональных данных и бюджет. Список мест и геолокация на сервер не отправляются
и не хранятся здесь — они остаются только локально, как и раньше.

**Я не могу развернуть этот сервер за вас** — у меня нет доступа в интернет из
песочницы, где я работаю. Ниже — всё, что нужно, чтобы сделать это самому.

## Почему именно так устроено

- **Аутентификация — через уже подключённые Яндекс ID и VK ID**, отдельного
  логина/пароля сервер не заводит. Мобильное приложение получает access_token
  напрямую от провайдера (это уже работает), затем отдаёт его сюда; сервер
  сам идёт к провайдеру и спрашивает «чей это токен» — благодаря этому пароль
  пользователя не проходит через наш сервер ни в каком виде.
- **SQLite, а не Postgres/MySQL.** Для одного пользователя на устройство и
  небольшой аудитории отдельная СУБД — это лишняя сложность в эксплуатации
  без реальной пользы. Если аудитория вырастет на порядки, замена на Postgres
  потребует переписать только `src/db.js` и SQL-запросы в `src/routes/*.js`,
  остальной код (маршруты, авторизация) не тронет.
- **Синхронизация бюджета — целым снимком** (GET отдаёт всё, PUT заменяет всё).
  Это самая простая стратегия, которая реально работает для одного телефона
  на пользователя. Полноценное слияние изменений с нескольких устройств —
  отдельная, более сложная задача, если она когда-нибудь понадобится.

## Обязательное требование: хостинг только в России

Часть 5 статьи 18 Федерального закона № 152-ФЗ (в редакции 242-ФЗ) требует, чтобы
базы данных с персональными данными граждан России физически находились на
территории РФ. Поэтому годятся только российские облака:

- **Yandex Cloud**, **VK Cloud** — крупные, с готовыми образами Ubuntu/Docker.
- **Selectel**, **Timeweb Cloud** — обычно дешевле для маленького проекта,
  тоже подходят: важно, где физически стоит сервер, а не кто его продаёт.

Любой из них с виртуальной машиной на 1–2 ГБ памяти справится — сервис лёгкий.

## Развёртывание (Docker, рекомендуемый способ)

1. Арендуйте виртуальную машину в одном из перечисленных облаков (Ubuntu 22.04+),
   установите на неё Docker и Docker Compose (`apt install docker.io docker-compose-plugin`
   или инструкция самого облака).
2. Скопируйте на сервер папку `backend/` целиком (`scp -r backend user@server:~/`).
3. `cp .env.example .env`, впишите `JWT_SECRET` (сгенерировать: `openssl rand -hex 32`).
4. В `Caddyfile` замените `api.example.ru` на домен, который указывает на IP сервера
   (домен обязателен — без него Caddy не сможет получить сертификат Let's Encrypt).
5. `docker compose up -d --build`.
6. Проверка: `curl https://ваш-домен/health` должен вернуть `{"ok":true}`.

## Локальный запуск для разработки (без Docker)

```bash
cd backend
npm install
cp .env.example .env   # впишите JWT_SECRET
npm run dev
```

Сервер поднимется на `http://localhost:3000`. Для проверки с телефона на той же
Wi-Fi сети вместо localhost используйте IP компьютера в локальной сети.

## API

Все маршруты, кроме `/api/auth/*`, требуют заголовок `Authorization: Bearer <токен>`,
который выдаётся при входе.

| Маршрут | Метод | Назначение |
|---|---|---|
| `/api/auth/yandex`, `/api/auth/vk` | POST | Обменять access_token провайдера на сессию `{ accessToken }` → `{ token, profile }` |
| `/api/profile` | GET | Профиль текущего пользователя |
| `/api/consent` | GET / PUT | Запись о согласии на обработку данных |
| `/api/budget` | GET / PUT | Весь бюджет целым снимком |
| `/api/account` | DELETE | Полное удаление пользователя и всех его данных |

## Резервное копирование

База — один файл SQLite (`/data/lifenavigator.db` в контейнере). Простейшая
схема бэкапа — копировать его по расписанию:

```bash
docker compose exec backend sqlite3 /data/lifenavigator.db ".backup /data/backup-$(date +%F).db"
```

и уносить бэкапы за пределы сервера (в объектное хранилище того же облака,
раз оно уже российское — сохранит требование по локализации).

## Чего сознательно нет

- **Восстановление доступа/refresh-токены.** Сессия живёт 30 дней и всё —
  после истечения нужен повторный вход через Яндекс/VK. Для MVP этого достаточно.
- **Multi-tenant/несколько окружений.** Это один сервис для одного приложения,
  без разделения на dev/staging/prod внутри кода — окружения разводятся тем,
  какой `.env` и домен вы используете.
- **Метрики и логирование в отдельную систему.** Сейчас только `console.log`/
  `console.error`, которые Docker сохраняет в свои логи (`docker compose logs`).
