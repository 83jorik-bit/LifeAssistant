# LifeAssistant: сборки и хранение артефактов

## Проверочная сборка

Каждый push в `main` и каждый pull request в `main` запускает workflow **Android CI**.
Он выполняет проверку серверного JavaScript, собирает `assembleDebug` и прикладывает
`app-debug-apk` к запуску Actions на срок до 24 часов.

## APK через GitHub Release (как в SoulAndroid)

Чтобы создать распространяемый тестовый APK:

1. Откройте вкладку **Actions**.
2. Выберите **Android CI**.
3. Нажмите **Run workflow** и выберите нужную ветку.
4. После успешной сборки откройте **Releases**.

Ручной запуск создаёт prerelease `debug-N` с APK. Обычные push/PR-запуски не создают релиз.
Тестовые debug-релизы не являются production-релизами RuStore.

## Срок хранения

Workflow `Cleanup build history` запускается ежечасно и также доступен вручную.
Он удаляет завершённые запуски Actions и их артефакты/логи, если они старше 12 часов
**или** если они не входят в 10 последних завершённых запусков.

Тот же предел применяется к prerelease с тегом `debug-N`. Обычные production-релизы
(не prerelease) этим правилом не удаляются.

GitHub для отдельного артефакта принимает срок хранения в целых днях, поэтому задан
минимум платформы — 1 день; ежечасная очистка удаляет данные раньше этого срока.
Фактическое выполнение scheduled workflow может задерживаться самим GitHub.
