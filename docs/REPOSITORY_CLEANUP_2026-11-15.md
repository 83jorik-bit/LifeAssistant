# Очистка репозитория LifeAssistant — 15 ноября 2026 года

## 1. Источник истины

Актуальная структура проекта — корень репозитория `83jorik-bit/LifeAssistant`, ветка `main`.

Локальная структура, обнаруженная при аудите:
- внешний репозиторий: `E:\GitHub\LifeAssistant`;
- вложенный отдельный Git-репозиторий: `E:\GitHub\LifeAssistant\LifeAssistant`.

Вложенный репозиторий не является самостоятельной частью целевой структуры и подлежит удалению после переноса согласованных полезных изменений. Его собственная папка `.git` не должна оставаться внутри рабочего дерева внешнего репозитория.

## 2. Что сохранено из сравнения

Сравнение показало, что внешний репозиторий содержит более новую и согласованную линию разработки:
- `AssistantActionResult.kt` — типизированный результат выполнения действий;
- `AppDataChanges.kt` — сигналы изменения локальных данных;
- актуальные версии `AssistantContext.kt`, `VoiceCommandDispatcher.kt`, хранилищ, ViewModel и экранов;
- защиту от ложного сообщения об успешном выполнении действия;
- обязательное подтверждение перед созданием задач и событий календаря.

Полезное расширение автономного финансового ответа `asksDaily` (доход/расходы, остаток от дохода, остатки по заданным лимитам и дневной ориентир) уже присутствует в актуальном `app/src/main/java/com/lifenavigator/app/data/ai/LocalAssistantEngine.kt` внешнего репозитория. Повторно переносить или заменять весь файл не требуется.

## 3. Что не переносится из вложенного репозитория

Не переносить изменения, которые выполняли создание задач или событий календаря без явного подтверждения пользователя:
- прямой вызов `calendarStorage.add(...)` и планирование напоминания сразу после распознавания команды;
- прямой вызов `taskStorage.add(...)` и планирование напоминания без подтверждения.

Не переносить резервную копию `LocalAssistantEngine.kt.bak`, локальные debug-файлы, `server/node_modules`, локальные базы `server/data` и прочие генерируемые/машинно-зависимые файлы из вложенного репозитория.

## 4. Серверные файлы

В ходе локального сравнения:
- `server/package.json` и `server/package-lock.json` совпадали;
- серверные исходники совпадали;
- локальная база SQLite не является исходным кодом и не должна переноситься в Git;
- `node_modules` восстанавливается через npm и не хранится в Git;
- `.env` и другие секреты/локальные настройки не должны попадать в Git.

В рекурсивном дереве GitHub (157 записей, включая каталоги) не обнаружены:
- вложенный путь `LifeAssistant/`;

- `server/package-lock.json` — lock-файл зависимостей;
- `app/src/debug/AndroidManifest.xml` — debug-only манифест; его удаление не включено в эту очистку;
- `keystore/lifenavigator-debug.keystore` — используется текущей конфигурацией debug signing в `app/build.gradle.kts`, поэтому не удаляется без отдельной миграции подписи.

## 6. Правила предотвращения повторного загрязнения

- Не добавлять вложенный проект `LifeAssistant/` в корень репозитория.
- Не коммитить `.git`, IDE-кэши, Gradle-кэши, каталоги сборки, `node_modules`, локальные базы и реальные `.env`.
- Сохранять исходники, конфигурацию сборки, workflows, документацию и необходимые lock-файлы.
- Все содержательные изменения сначала сверять с последними решениями в переписке проекта.
- Каждый принятый набор изменений фиксировать отдельным понятным Git-коммитом.

## 7. Локальное завершение очистки

GitHub main не содержит вложенный каталог `LifeAssistant/`. На локальном компьютере вложенный каталог остаётся отдельной локальной копией и должен быть удалён после того, как внешний репозиторий обновлён через `git pull` и проверено, что актуальный `LocalAssistantEngine.kt` содержит согласованное расширение `asksDaily`.

Перед удалением локальной вложенной копии следует убедиться, что ранее созданная резервная копия `E:\LifeAssistant_AuditBackup_20261114` доступна. Локальные `.env`, `local.properties` и пользовательские данные внешнего репозитория не удалять.
