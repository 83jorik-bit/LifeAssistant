# Развёртывание сервера LifeAssistant

Этот сервер нужен для облачного режима помощника (YandexGPT), серверной сессии входа и синхронизации. Автономный режим приложения работает и без него.

## 1. Подготовить сервер

Нужен сервер/VPS с Docker Engine и Docker Compose, а также доменное имя с HTTPS через Caddy, Nginx или другой reverse proxy. Порт приложения привязан к `127.0.0.1:3000` и не предназначен для прямого публичного доступа.

В корне репозитория создайте локальный файл окружения:

```bash
cp server/.env.example server/.env
```

В `server/.env` задайте реальные значения:

- `JWT_SECRET` — длинный случайный секрет для подписи серверных сессий. На Linux можно получить командой `openssl rand -hex 32`.
- `YANDEX_GPT_API_KEY` — API-ключ сервисного аккаунта Yandex Cloud с разрешением использовать языковые модели.
- `YANDEX_GPT_FOLDER_ID` — идентификатор каталога Yandex Cloud.

Не коммитьте `server/.env` и не помещайте `YANDEX_GPT_API_KEY` в Android `local.properties`, GitHub Actions Android-сборку или APK.

## 2. Запустить контейнер

Из корня репозитория:

```bash
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:3000/health
```

Когда все настройки заданы корректно, health-check должен возвращать JSON вида:

```json
{"ok":true,"assistantConfigured":true}
```

Поле `assistantConfigured` сообщает только наличие обеих настроек и не раскрывает их значения. Если оно равно `false`, проверьте переменные в `server/.env` и перезапустите контейнер:

```bash
docker compose up -d --build
```

Данные SQLite хранятся в постоянном Docker volume `lifeassistant-data`. Не удаляйте этот volume при обновлении контейнера; настраивайте резервное копирование данных.

## 3. Подключить HTTPS-адрес к приложению

Настройте DNS для домена и HTTPS reverse proxy, который направляет запросы на `http://127.0.0.1:3000`. Проверяйте внешний адрес:

```bash
curl https://api.example.com/health
```

Замените `api.example.com` на свой домен. В GitHub откройте `Settings → Secrets and variables → Actions` и задайте/обновите secret `BACKEND_BASE_URL` значением внешнего HTTPS-адреса, например `https://api.example.com` (без завершающего слеша).

После изменения secret запустите Android workflow ещё раз, чтобы адрес попал в `BuildConfig`. Приложение не сможет обращаться к новому серверу, пока не установлена сборка с корректным `BACKEND_BASE_URL`.

## 4. Проверить вход и помощника

1. Убедитесь, что `/health` возвращает `assistantConfigured: true`.
2. Установите APK, собранный после настройки `BACKEND_BASE_URL`.
3. В приложении сначала примите согласие и войдите через Яндекс ID или VK ID. Серверная сессия создаётся при завершении входа.
4. Откройте «Помощник» и отправьте запрос. При успешном ответе строка режима в интерфейсе изменится на «Облачный ИИ».

Если вы уже входили до настройки сервера, выйдите и войдите ещё раз после установки новой сборки — так создастся серверная сессия. Если сервер временно недоступен, приложение продолжит отвечать локально по бюджету и сохранённым местам.
